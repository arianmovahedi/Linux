# DeamonSet
DaemonSets allow us to place and run prioritized infrastructure focused Pods on targeted nodes. A DaemonSet is represented by Pods that run on the cluster nodes and provide some background capabilities for the rest of the cluster. A DaemonSet is somewhat similar to a ReplicaSet that makes sure a specific number of Pods are running. In DaemonSets the deployment isn't driven by consumer load in deciding how many Pod instances to run and where to run, its main purpose is to keep running a single Pod on every node or specific nodes. By default DaemonSets place a Pod instance on every node. That can be controlled and limited to a subset of nodes by using the `nodeSelector` or `affinity` fields. Pods created by a DaemonSet can run before the scheduler has started, which allows them to run before any other pod is placed on a node. The DaemonSets `restartPolicy` is only set to `Always`. These Pods are ignored by the descheduler and will not be evicted also the cluster autoscalar will manage them separately.

Kubernetes will set the `nodeName` for the Pods scheduled on each node in the Pods specification which allows the DaemonSet to be scheduled before the scheduler starts. In newer versions of kubernetes the `nodeAffinity` field is set instead of the `nodeName`.

Another way of achieving a DaemonSet behavior is using the `StaticPods`. These pods are only managed by the Kubelet on the nodes and the configuration of each can be defined in a local direcotry. The API Server will not observe the Static Pods and no health control or health check is ran on them. the Kubelet will watch them and restart them when they crash.
